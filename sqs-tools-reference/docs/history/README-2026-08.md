# sqs-tools

Reverse-engineered reference for Squarespace 7.1's admin content API, built from
live network captures on ou.studio (Onwards & Upwards). Two goals:

1. **`scripts/`** — standalone console-injectable scripts for common admin
   tasks (pull a page's full config, duplicate a page).
2. **`lib/blocks/`** — a structured reference of every block type's JSON
   shape, captured directly from the editor, so new page content can be
   generated programmatically instead of guessed at.

## scripts/

- **get-collection-data.js** — pulls a single collection's metadata
  (`commondata/GetCollection`).
- **get-page-data.js** — pulls a page's full collection metadata + layout
  tree (sections/rows/columns/blocks) via `pages/by-collection-id`.
- **duplicate-page.js** — clones any page's full content into a new,
  unlinked page. Two-step (`preview()` then `commit()`) so nothing writes
  until you've reviewed what it's about to do. See in-file usage comments.
- **build-test-page.js** — end-to-end test: builds a new blank page with
  a text/gallery/image-block mix across 4 sections, sourcing a real image
  from the media library (or a fixed known-filename placeholder) and
  referencing it once for reuse. `commitWithImage()` can also fully
  populate the Gallery block with real images — see
  [lib/blocks/gallery-variants.js](lib/blocks/gallery-variants.js) for the
  confirmed pipeline (a gallery's images live in their own backing
  collection, created and populated via two writes).

All four are meant to be pasted into the browser console while logged
into the Squarespace admin (`/config/pages` or any live page).

## lib/blocks/

- **block-library.js** — every block type (38 total), its `type` number,
  `definitionName`, default JSON value, and a rough usage-frequency tag
  (`often` / `periodic` / `rare` / `legacy`) based on how the studio
  actually uses them. `createBlock(kind, overrides)` helper included.
- **text-formatting.js** — every RTE formatting pattern (headings, colors,
  alignment, lists, highlight, scaled text, etc.) as composable HTML
  snippet builders.
- **image-variants.js** — all six `designLayout` options (inline, poster,
  card, overlap, collage, stack), plus the confirmed real-`imageId`
  sourcing pipeline (list library assets → reference into site content →
  get a block-ready id).
- **button-variants.js** — alignment, size, stretch, link handling.
- **gallery-variants.js** — all four `design` modes (grid, stacked,
  slideshow, slider) and the full aspect-ratio preset list.
- **summary-variants.js** — all four `design` modes (list, autogrid,
  carousel, autocolumns), confirmed metadata options, and the
  (non-Gallery-matching) decimal-ratio aspect ratio format this block uses.
- **link-targets.js** — the three link kinds shared across every block
  with a link field: internal page, external URL, uploaded file (`/s/...`).

## notes/

Working notes on API areas that are still being captured/confirmed,
ahead of being promoted into a proper `lib/` reference once coverage
feels solid:

- **section-settings.md** — section-level `styles` (height, content
  width, alignment, background mode/overlay, the 10 named section
  themes) as distinct from block content.
- **header-footer-settings.md** — the site-wide `header` config object
  and confirmation that footer content uses the same section shape as
  page sections.
- **custom-css.md** — the Custom CSS field's endpoints and its LESS-style
  nested syntax (nested selectors, `&`, nested `@media`).
- **code-injection.md** — header/footer code injection endpoints.
- **blog.md** — blog/page collection creation flow (catalog-copy →
  generate-url → rename → add-to-nav); the default-seed-posts problem
  is still open.
- **site-styles.md** — the sitewide Site Styles editor (Fonts, Colors,
  Buttons, Forms, Miscellaneous), all confirmed now. Colors and Fonts
  each have their own dedicated endpoint with the same two-layer
  indirection pattern: `website-colors` (10 palette swatches + per-theme
  variable→color mappings) and `website-fonts` (3 master fonts/sizes +
  ~140 named UI-role→font mappings). Buttons/Forms/Miscellaneous instead
  all share `GetTemplateTweakSettings`/`SetTemplateTweakSettings` — a
  flat `variableName`→value map (`tweakValues`), split into panels only
  by `category`/name-prefix, saved via a form-urlencoded POST (not a
  JSON PUT like everywhere else) that re-sends the *entire* map.

## Known gaps

- No captured endpoint yet for uploading a brand-new image/file (only
  referencing ones already in the library) — would need multipart form
  handling not seen in the network captures so far.
- No sitewide "list all pages" endpoint beyond `commondata/GetCollections`
  (which does cover it, just documenting it's the one to use).
- A handful of `legacy`-tagged blocks in block-library.js only have sparse
  defaults captured (calendar, rss, soundcloud) — fine as placeholders,
  worth a fresh capture if one is ever actually needed.

## Write-endpoint safety notes

A few endpoints discovered during this process are **write/mutation**
endpoints, not read-only, and are deliberately NOT wrapped into any script
here without an explicit confirm step:

- `catalog-preview/blankLayoutEngineSection` — creates a live section
- `content/add/layoutEngineSection` — saves a section onto a page
- `commondata/SaveCollectionSettings` — creates/edits a page
- `widget/UpdateNavigation` — edits live site navigation
- `uploads/images/asset-reference` — creates a media content record
  (safe to use once per asset, but re-calling for the same asset likely
  creates duplicates)
- `template/SetTemplateCustomCss` — overwrites the entire Custom CSS
  field (form-encoded, not JSON — breaks the `Get*`/`Save*` naming
  convention below). Full-field overwrite: GET current value, modify,
  resend the whole thing. See [notes/custom-css.md](notes/custom-css.md).
- `config/SaveInjectionSettings` — overwrites header/footer code
  injection (and lockPage/postItem/order-confirmation/order-status/sso
  fields). Form-encoded, full overwrite of all fields each call. See
  [notes/code-injection.md](notes/code-injection.md).
- `website-colors` (PUT) — overwrites the entire site color system
  (palette + all 10 named theme definitions) in one call. Full-field
  overwrite: GET current value, modify, resend the whole thing. See
  [notes/site-styles.md](notes/site-styles.md).

`pages/by-collection-id/<id>` also accepts **PUT**, which is the
mechanism `duplicate-page.js` uses to write cloned content — this is the
core "write a full page's content" primitive for anything built on top of
this reference.
